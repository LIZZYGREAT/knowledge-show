## 一、当前实现的具体问题

| 问题 | 代码位置 / 当前机制 | 结果 | 修改原则 |
|---|---|---|---|
| 页面过窄 | `frontend/src/common/theme.css`：`.landing {max-width:1240px;padding:60px 48px}`、`.composer {max-width:1000px;padding:0 48px}` | 桌面端两侧大量闲置空间，表单实际有效宽度进一步被内边距压缩 | 使用不同的合理容器宽度；内容应明显利用 1440–1920px 桌面空间 |
| 首页视觉主体不足 | `frontend/src/features/landing/LandingHero.tsx` 的 `KnowledgeScene()` 包含固定 `idea-orbit`、圆形 halo、虚线圆环和一个无限循环 `animateMotion` 小球 | 大面积绘图区由细线占据，视觉对象过小；运动没有清晰的“动作 → 变化 → 结果” | **整体重做开场动画场景**，不要在原螺旋上继续叠加节点或多条轨道 |
| 图文相互穿插 | 同一 SVG 中将 `01 — THE SPARK` 直接放置在坐标 `(52,245)`；路径画面缺乏文字避让区 | 文字被轨迹干扰，阅读层级不清晰 | 辅助文字独立于动画内容布局，必要时删去没有实际信息价值的英文装饰标签 |
| 标识气质不一致 | `.brand` 继承 `Aptos/Segoe UI`，`.brand-mark` 单独使用 `Georgia`，字重为 `600`，字体比例/间距由多个选择器独立控制 | `k·` 和 `knowledge.show` 之间缺少统一排版系统，Windows 字体回退时不协调 | 明确独立品牌字标排版，检查中英文及各系统字体回退 |
| 进阶表单布局失衡 | `.preferences {grid-template-columns:1fr 1fr}`，有 5 个字段；`field()` 对所有文字输入均给 `textarea rows=3` | 最后一项单独占左列、右侧空白，多个大输入框造成向下堆积 | 改为按信息密度分组的非均等网格，紧凑项使用单行 input，长文本使用受控 textarea |
| 页面过渡缺乏对象继承 | `App.tsx` 使用 `document.startViewTransition()` 直接切换 React 页面；没有显式共享视觉元素 | 当前更接近页面淡入淡出；没有实现“首页的核心对象自然进入创作区” | 单独建立共享视觉锚点与转场状态，不将所有内容一起形变 |
| 超宽屏额外留白 | `@media(min-width:1600px)` 进一步增加 `.landing` 的 top padding 和 `.hero-copy` 底部 padding | 容器本来偏窄，纵向空间还被放大 | 超宽屏依据可视区域动态均衡图文，禁止用加大 padding 掩盖构图问题 |

本次仅改视觉与展示层，保留 `CreationComposer` 已有字段绑定、`toUserInput()`、`CreationConfirm`、Key 内存状态，以及生成进度仍为演示状态的诚实提示。禁止暗改公有契约。

## 二、设计目标与整体美术取向

延续 PaperSkill 的暖白背景、深绿文字、草木色与浅金色强调、中文大标题、克制的细线装饰。**此次增加的是动态视觉主体的可识别性，而不是更多几何线条。**

产品首页应当做到：远看有清楚的标题与独特的主视觉，近看能发现连续、自然、有因果的运动；鼠标交互可以增加细节但不应影响使用。正式创作页应当做到：输入主题是最大视觉重心，用户的选项按相关性而不是“一项一行”排列，不显得像后台设置面板。

参考资源的提取方式：

- PaperSkill `work/l2p`：取暖白与墨绿 Token、衬线大标题的气质、低对比留白，不直接移植阅读页栏宽。
- [`magician336/competitor-analysis-system` 的 `SignalFieldHero.vue`](https://github.com/magician336/competitor-analysis-system)：借鉴程序化动画的**阶段状态变化**、鼠标交互、ResizeObserver 和 reduced-motion 处理，不照搬复杂多轨道与蓝紫科技感。
- [Codrops：Typography Animation 案例](https://tympanus.net/codrops/2025/03/05/case-study-stefan-vitasovic-portfolio-2025/)：借鉴动画中的“分散的字形/元素逐渐形成可识别整体”；不把页面做成纯文字特效。
- [Motion SVG Animation](https://motion.dev/docs/react-svg-animation)：参考线条绘制、路径形变与 SVG 运动技术；只有确实需要时才考虑引入新依赖。
- [GSAP Flip](https://gsap.com/docs/v3/Plugins/Flip/)：参考跨布局共享元素过渡的思路，不要求第一版必须使用 GSAP。

## 三、首页主视觉：推荐彻底换成「会展开的纸上小剧场」

### 1. 视觉概念

把右侧图形从“空心螺旋轨道”重构为一个**有物体、有层次、有行为的纸艺小舞台**。保留墨绿、米白、浅金，但主视觉必须具备一个清楚的实体轮廓。

**核心对象**：一张带有轻微纸张厚度和折痕的浅色纸片，从页面中缓缓翻起、展开。纸面上有一个深绿色的小型几何对象（可以是圆珠/纸质小球），它受纸面折痕和几何结构影响发生连续移动，最终推动纸面展开成一个具有前后层次的微型空间。纸张、折痕、几何对象要在画面中占据真正有辨识度的面积，而非只是几条装饰曲线。

这个概念只用于**产品首页品牌动画**，不是对以后生成视频的风格限制；其寓意是“一个想法形成可以运动的作品”。

**必要约束**：不要把纸面做成几张相互切换的 PPT 卡片；整个演出始终围绕同一组可追踪的实体，持续改变形态、位置和关系。

### 2. 动画编排（时间为视觉建议，不是硬编码帧数）

| 阶段 | 主体动作 | 观众感知 |
|---|---|---|
| 进入（约 0–0.5s） | 纸片的边缘与初始几何对象从淡入逐渐实体化，背景仅有轻微的纸张质感 | 画面出现明确的实体主体 |
| 展开（约 0.5–1.5s） | 纸片沿折痕自然弯曲展开，几何对象沿新形成的结构滑动，投影随形状同步变化 | 一个行为引起下一个变化 |
| 成形（约 1.5–2.5s） | 折叠层形成前、中、后的关系，几何对象在其间穿行，留下很轻的轨迹；整组视觉安定到主画面 | 看见“想法开始动起来” |
| 等待（之后） | 低幅度、低频的呼吸、纸层弹性回位或对象缓慢移动，不重复完整开场 | 画面有生命，但注意力仍留给标题与 CTA |
| 点击“开始创作” | 保留一个有身份的深绿运动对象，沿连贯轨迹缩小移动到创作页主题输入区附近；纸艺主体退场，创作页内容错峰进入 | **同一视觉对象从开场进入实际创作** |

这不是要求制作复杂 3D 仿真。可通过 SVG 分层填充、裁切、渐变阴影与少量参数化形变实现，也可以先在平面稿里把布局和关键姿态画清楚，再加入运动。**先做三张关键姿态图审查，避免 Codex 直接生成复杂路径后反复试错。**

### 3. 版面构图

- 在 1440–1920px 常见桌面宽度下，首页整体有效内容宽度建议在 **1360–1500px** 范围内，左右留白合理对称。
- 左侧为标题、简短说明及主按钮，约占 42–45%；右侧为更强的舞台主体，约占 55–58%，主体图形在右侧视觉区内占据 **至少约 65% 的可用高度**（根据实际画面调整）。
- 右侧舞台不需要额外巨大的矩形描边框；通过形体和留白获得边界，柔和投影可以增强纸艺立体感。
- 辅助的 `01 — THE SPARK` 直接移除，或置于舞台外部的独立图注区；不允许其被动画路径或形体覆盖。英文口号不应与主体争夺注意力。
- 停止继续复制 `idea-orbit` 的静态几何；旧 `KnowledgeScene` 可重构为 `LivingPaperStage` 或等价命名，确保语义与实现匹配。

### 4. 动画技术与性能约束

- 在 `LandingHero.tsx` 拆分「静态舞台形态」与「动画控制状态」。先能在任一时间点稳定渲染出姿态，再实现连续补间。
- 考虑 SVG + CSS / Web Animations API 即可；不为了一个首页引入大型 WebGL 场景。若确实需要路径插值，可采用已有轻量 Motion/GSAP 方案，但要记录引入原因。
- `prefers-reduced-motion` 时直接展示完成后的稳定姿态，按钮与表单照常工作。
- 页面离开、不可见时停止不必要的动画更新；移动端可显著简化形体层数与阴影。
- 无论鼠标是否悬停、无论用户是否立即点击，进入创作页均不应卡在开场时序上。

## 四、品牌字标：单独完成字体排版，不再依赖全局正文回退

在 `App.tsx` 与 `theme.css` 调整 `.brand`、`.brand-mark`、`.brand-dot`：

- 保留 `k·` 与 `knowledge.show` 的组合，但让标志与字标处于统一字高、基线与间距逻辑。可弱化 `k·` 的强调程度，避免两套视觉主角互相竞争。
- 建议 `knowledge.show` 使用明确的**品牌拉丁字族**，不直接继承 `Aptos` 的正文设置；优先测试 Windows 中稳定存在的字体回退，如 Georgia 或已获得授权、实际加载的品牌字体。不要只指定用户机器未安装的字体。
- 主标识建议重绘为清爽的中等字重（例如 500），避免截图中显得拥挤的 600 字重和过紧负字距；分隔点用单独 span 控制间距与强调色，但不要让“knowledge”和“.show”拆开得像两段按钮。
- 中文大标题单独使用 display 字体族。Windows 无高质量中文宋体时须验收回退，不能从 `SimSun` 等较差回退中默认得到理想效果。可沿用 PaperSkill 的实际可用字体与授权资源，**不将第三方字体文件随文档复制**。
- 在 1920px、1440px、1280px、768px、375px 下检查品牌标识宽度、英文基线、点的圆度和可读性；不能只看本机一个浏览器。

## 五、正式创作页面：加宽、提高输入密度、解决孤立字段

### 1. 宽度与主次

- `theme.css` 中 `.composer` 从 `max-width:1000px` 提升到建议 **1280–1380px**（包括内边距），横向 padding 用 `clamp(24px,3.5vw,56px)`，避免 1920px 视口只用中间约 900px。
- 标题与主题输入区仍然居中，但辅助输入区域可较宽，避免所有控件挤在一列。主题框是绝对主焦点，其他要求需降低视觉重量。
- 在宽屏中将首组 `.form-columns` 改为偏向实际内容的 52%/48% 或相近比例，按钮行不要因为全部堆叠而突然变高。
- 页面头部 `composer-heading` 的 SVG 小装饰在本次新主视觉后应更小或去掉，避免占据过多上方空间；不需要同一动画在两个页面重复执行。

### 2. 更多创作偏好：明确栅格占位

重做 `.preferences` 的字段布局，不让最后的“希望避开内容”独占一列：

| 行 | 左侧 | 右侧 |
|---|---|---|
| 第一行 | 知识深度（紧凑选项） | 美术风格偏好（单行或适度自动增高输入） |
| 第二行 | 自己的创意（较宽，自由描述） | 可为空，或与左侧合成整行，不创造人为留白 |
| 第三行 | 希望包含的内容 | 希望避免的内容 |

更推荐将第二行的“你的创意”**横跨整行**，其他行两列平均布置；两个必须/避免字段采用 2–3 行的紧凑文本区而不是 150px 高的大空白框。

实现建议：为高级字段提供可复用的单行 `input` 与多行 `textarea`，不要复用 `field()` 导致所有字段默认 `rows=3`。用户希望包含或避免多个内容时仍可按换行拆分，但 UI 文案可以直接写「想出现的内容」「希望避开的内容」，不必强调内部解析格式“每行一项”。

### 3. 视觉细节

- 缩小高级偏好标签与输入框的距离，压缩大 textarea 造成的视觉空洞；保留较好的字体、圆角和对比度。
- 主表单出现与折叠区域展开可使用 180–300ms 的尺寸/透明度过渡，但不应导致焦点跳动或字段输入丢失。
- 避免在宽屏中为所有字段添加厚卡片背景；主要依靠网格、留白、细线和轻表面色组织层次。
- 保留原有 `toUserInput` 的合法值处理及可访问的 `label`、`legend`、按钮 pressed state。

## 六、开场到创作页面的连续转场

当前 `App.tsx` 仅调用 `document.startViewTransition()`，页面变更时未指定跨页面共享对象。建议：

1. 让开场纸艺主体中的**一个可识别的小型实体**成为共享锚点，创作页输入框旁边保留同一角色的小型静态/动态姿态。
2. 为锚点建立唯一的 `view-transition-name` 或等价的显式转场映射，并在原页面退出与新页面进入时绑定同一身份；背景舞台和大段文字采用不同节奏淡出/进入。
3. 点击按钮后，先执行 500–850ms 的对象移动/缩放，然后创作表单主体进入，不允许转场仅成为整页交叉淡化。
4. 不支持 View Transitions 或 reduced-motion 时直接切换页面，不阻碍表单与设置抽屉。
5. 确保共享对象只出现在当前页面所需位置，不允许同一 `view-transition-name` 同时用于两处可见元素。

转场应当让用户感到同一个创作概念自然延续，不需要引入复杂全屏切页特效。

## 七、代码范围与执行步骤

| 文件 | 预计工作 |
|---|---|
| `frontend/src/features/landing/LandingHero.tsx` | **重做主视觉组件**与动画阶段，确保 SVG 内无文字遮挡；拆分可测量的舞台形态 |
| `frontend/src/common/theme.css` | 更新首页/表单容器、栅格、品牌字体、动效和响应式规则；删除失效的螺旋相关样式，避免留下大量无用 CSS |
| `frontend/src/features/creation/CreationComposer.tsx` | 高级偏好按字段性质使用 `input`/`textarea`，重排视觉顺序；保持 `Draft` 与 `toUserInput` 不变 |
| `frontend/src/App.tsx` | 调整字标结构及页面间的共享元素转场；保留弹窗、Key Context 和原路由状态 |
| `frontend/tests/e2e/creation.spec.ts` | 增加宽屏布局、进阶偏好无错位、开场到创作连续转场及 reduced-motion 下可正常操作的检查 |
| `frontend/tests/creation.test.ts` | 原有表单数据和选项映射回归，必要时补字段输入测试 |

### 推荐执行顺序

1. **先做视觉草案**：纸艺小剧场至少给出起始、展开、稳定三种姿态截图；确认构图和主体形态足够好看后，再做连续动画。
2. **先解决静态布局与字标**：1440/1920 宽屏下逐项检查容器、字体、字段高度、第三行对齐及整体页面可读性。
3. **实现动态舞台**：再加入有因果的纸张展开与实体运动。禁止仅替换一条轨迹或改变 SVG 半径作为“整体重做”。
4. **实现跨页过渡**：建立真正可追踪的共享实体，保证点击后自然进入创作区。
5. **回归与清理**：保留 API 内存设置、表单契约、原有测试；清除旧样式与无用节点；按实际效果微调。

## 八、验收标准

### 视觉与排版

- [ ] 1920、1440、1280px 桌面视口，首页和创作页不再出现与内容规模不成比例的两侧大空白；左右视觉重量均衡。
- [ ] 首页有一个**面积足够、可辨认、具有物理/形态行为的主视觉实体**，而不是单一螺旋线配一个移动圆点。
- [ ] 动画至少出现一次明确的“动作触发状态变化、变化带来新结果”的连续过程；等待态不反复制造显眼跳帧。
- [ ] `01 — THE SPARK` 已移除或置于完全避开动画的独立安全区，英文/中文辅助说明没有任何遮挡。
- [ ] Logo 在 Windows 与其他目标系统中具有合理字重、统一基线与舒适字距；正文和大标题的字体回退可接受。
- [ ] 高级偏好区不存在最后一个输入框悬空独占半行；输入区域高度与内容长度合理。
- [ ] 768、375px 不发生横向滚动、文字重叠、控件超出容器，主视觉保持正确构图。

### 动画与工程

- [ ] 点击“开始创作”能看到同一视觉实体自然进入创作页，而非只有两页淡入淡出。
- [ ] `prefers-reduced-motion` 下静态姿态可看、操作完整。
- [ ] 浏览器失去焦点后不持续进行不必要的高频运算。
- [ ] 不依赖任何未提交的私有字体或本地绝对路径。
- [ ] `npm run build`、`npm test`、`npm run test:e2e` 通过，且原来的 API 设置与输入数据不受影响。
- [ ] 不提前声称已经生成正式视频或已接通工作台；仍以已实现状态为准。

### 对 Codex 的审查要求

提交前请自行查看**至少两种桌面宽度**及移动端的最终截图，对每一处视觉问题做修改前后对照；不要仅凭测试通过宣称视觉问题已解决。重点审查对象运动是否真的自然、静态构图是否已经成立、字体是否一致、动态文字是否与轨迹错位。修改需有明确 commit，最后报告实际修改文件、测试命令、结果及未完成项。
