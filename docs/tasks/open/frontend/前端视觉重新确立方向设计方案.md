## 一、审查结论与真正需要改变的方向

最新实现中，`LandingHero.tsx` 使用 `LivingPaperStage`，其核心逻辑在 `LivingPaperStage.tsx` 的 `paperPose()` 和 `PaperShape()`：通过固定折点、多个填充多边形、纸面立起和绿色小球滚动形成纸艺舞台。`paper-stage.css` 为纸面和球体提供渐变、阴影及轻微静置动效，`usePaperMotion.ts` 控制 2.6 秒展开动画。

这套机制解决了“视觉不是只有一条细线”的问题，却**没有满足目前希望的视觉观感**：大面积米色实体折面与锐利三角形带来偏机械、硬朗的几何模型感，缺乏轻盈灵动的形态、微妙层次和流动感。纸艺对象占据右侧大幅空间，却没有令人想反复观看的丰富运动细节。继续为纸盒补充阴影、纹理或更多折面，不是正确修订方向。

**新的美术方向**：以有机线条、柔软流动的色面、气泡、微粒与局部精致花纹构成视觉语言。首页需要一个具有辨识度的**连续流动主体**，带动其他元素运动；创作页则使用少量花边、波纹、细线和小叶片点缀版面，让页面精致、有趣但不抢夺输入焦点。

## 二、首页主视觉：唯一优先方案「流动的知识纹理」

### 1. 视觉概念

设计一个在暖白背景中缓慢生长、汇聚和流动的**有机流带 / 线面复合体**。它可以联想到水流、墨迹、丝带、流体纹理或知识生长，但不用固定形象解释这些比喻。

主视觉分为三个具有明确主次的层：

- **主流带**：一整块连续的、可变形的半透明青绿／深绿流动形体。它占据右侧主视觉绝大部分注意力，形体饱满但边缘柔软、有起伏；其轮廓在运动中会拉伸、卷曲、舒展，不应表现为静止的几何多边形。
- **流线与轮廓纹理**：跟随主流带内部运动的若干细线、等高线或流丝，使用深绿与低透明度浅青色，体现流向、层次与连续性。线条是流动形体的结构，不能独立变成随机绕圈的蜘蛛网。
- **微粒、气泡与点光**：数量克制的大小不同的圆点与轻盈小气泡，沿流场速度移动，在局部汇合、散开、轻微闪烁。暖金色只作为少数重点，不要满屏发光点或游戏粒子特效。

画面应有**一个整体上清晰的形态**，细看才有丰富的变化与纹理；远看不能只剩散乱的线、点和气泡。

### 2. 颜色、透明度和质感

沿用现有页面 Token：暖白 `#f7f7f2`、墨绿 `#1b4a34`、草绿 `#2e6b4e`、浅金 `#cfad72`。允许给首页主视觉增加一到两种更鲜明的**蓝绿/青绿**强调色（例如 `#1c9089`、`#72c3b1`，实际对照截图微调），让右侧从背景中明显浮现。

推荐的层次：主体深绿占视觉核心，青绿用于边缘与流动高光，浅绿用于次级柔和轮廓，暖金色用于少数运动节点。**色彩鲜明主要集中在右侧主视觉，不影响左侧标题的典雅风格。**

可以使用低对比渐变、透明度交叠、轻微模糊营造柔软感，但禁止整体大面积霓虹外发光、廉价科技感、玻璃拟态和厚重阴影。质感应接近细腻的设计作品，而非 WebGL 教程案例。

### 3. 主视觉的具体动效编排

下表用于明确“每个时刻具体发生什么”，不是要求按几张静态帧依次切换。形态、速度和位置必须通过连续时间函数计算。

| 时间（建议） | 主体变化 | 次级元素 | 视觉目的 |
| --- | --- | --- | --- |
| 0–0.8s | 右侧中下方出现一小束有方向的青绿流线，主形体由细渐宽 | 一小批微粒从附近缓慢被吸引 | 迅速建立视觉焦点，不让用户看到空场加载 |
| 0.8–2.2s | 主流带沿一个自然 S 型趋势生长和舒展，形成第一处明显卷曲 | 内部流丝逐渐跟随出现，边缘点轻微散开 | 从线发展为有层次的形体，形成“哇，原来是这样展开的” |
| 2.2–4.2s | 流带局部起伏、分叉又汇合，产生一次清楚的形态重组 | 少量气泡穿过流线并形成涟漪；暖金节点沿主轨迹出现一次 | **核心观看亮点**，让形体看起来有生命，变化前后连贯 |
| 4.2–5.5s | 流带舒展为最终富层次的构图，保持不对称且有张力的完整轮廓 | 细粒缓缓沿内部速度场漂移 | 画面定型，视觉重心仍位于右侧主体 |
| 5.5s 后 | 进入自然等待态：局部波动、缓慢呼吸和少量细线漂移 | 少量微粒持续运动，幅度受限 | 保持“活着”的感觉，不重复整段开场，不抢 CTA |
| 点击“开始创作” | 主体沿自己的流线收束为一个小型高亮节点或线形印记，朝创作页主题区域移动 | 背景流丝顺势回收，创作页面渐入 | 保持跨页连续性，避免僵硬整页淡出 |

第一版应着重打磨**0.8–4.2 秒的主变化**：前一动作必须推动后一变化，不能只让几条 SVG 路径异步播放或给很多独立圆点加随机位移。等待态可以克制，但整体必须有吸引力。

### 4. 静态关键姿态先于完整动画

先输出至少 3 个可截图检视的姿态：

1. **初始构图**：第一束形态出现，标题、CTA 不被遮挡。
2. **高光构图**：流带卷曲、细纹和粒子共同形成完整、精致且有辨识度的视觉重心。
3. **等待构图**：完整形态依然有张力，不靠动起来才能显得好看。

三张关键姿态的质量决定能否进入动画制作。若静止截图像几根随机贝塞尔线、杂乱节点云或平淡的网页装饰，直接重画构图，不通过加速运动来掩盖问题。

### 5. 版面构图与空间

- 保留现有 `.landing` 已扩展到 `max-width:1500px` 的基本方案，桌面端内容比例可在 **左 40–43% / 右 57–60%** 微调。不要因为新视觉再次让两侧出现大片无意义空白。
- 主视觉放在首页右侧，略向右边缘延展；允许部分**非关键的柔和流丝**延伸到视觉区域边缘，形成空间上的舒展感，但不能引起水平滚动。
- 主流带实体应覆盖右侧视觉区域中明显的一块面积（根据造型决定），不要缩成一条细丝而让画面中央再次变空。
- 左侧标题始终是可读性最高的文字，右侧主视觉是唯一强视觉主体；不要增加一堆“01 / THE SPARK”之类无作用的装饰标签，更不允许文字压在动态图形下方。
- 背景保持暖白，不在右侧另加大尺寸卡片边框、网格框、透视纸盒或厚重容器。充分利用负空间实现画面高级感。

## 三、正式创作页：轻量且精致的花纹装饰系统

当前 `.composer` 已改为 `max-width:1380px`，`CreationComposer.tsx` 已将“你的创意”做成跨行宽字段，“美术风格”也已改为单行输入。**这些改动应保留，勿退回旧版逐项堆叠表单。**

目前缺失的是整体美术气质：表单空间由许多输入框和分隔线组成，缺少有辨识度且与品牌一致的精致装饰。建议增加一个小型、可复用的 Ornament 系统。

### 1. 装饰元素组合

| 装饰 | 推荐位置 | 表现 | 作用 |
| --- | --- | --- | --- |
| **横向舒展曲线** | 创作页标题与主题输入之间，或主题区与更多偏好之间的一个主要转场位置 | 两到三条极淡的波线，局部浅绿填充，少数暖金细线 | 像参考图三一样形成自然、优雅的章节分界 |
| **细枝叶 / 小芽** | 上述横线一端、页面角落或偏好区域的单个边缘 | 2–3 片简单叶形，与线条连接，低饱和、适度留白 | 增加细腻气质，避免只剩几何 UI |
| **短线与点的局部花边** | 模式选择区、主题区外沿或页脚空白处 | 类似参考图四圆形图表外侧的少量短线、微粒与符号，但组成局部花边 | 强化“精致编辑设计”的感觉 |
| **焦点响应的小纹理** | 主题输入获得焦点时、点击模式选项时 | 局部细线微微展开、暖金点轻微亮起 | 与用户操作产生温和呼应 |

数量控制建议：**首屏只出现 1 处主要装饰 + 1–2 处非常轻的辅助细节**。展开更多偏好后，允许在下半部再出现一处独立的装饰。不要把每个字段包成植物框、每个按钮都长叶片。

### 2. 装饰与内容的层级

- 装饰只出现在**内容间隙、边缘或局部留白**，避免进入输入框文字区、点击区或覆在标签上。
- 装饰不承担信息传递；使用 `aria-hidden`，SVG `pointer-events:none`，确保不能拦截按钮和输入焦点。
- 主输入框、主要 CTA、模式选择始终优先于花纹；背景细线不能让文字对比度下降。
- 可从 `PaperSkillWork/work/l2p` 的 `EditorialFlourish.tsx`、`editorial-flourish.css` 提取**线条的密度、比例、枝叶语法与色彩层级**，作为改造参考；**不要原样复制整个 SVG 分隔图**，需要为本产品的宽屏表单重新设计构图。
- 可增加鼠标或滚动触发的极轻微“线条延展”动画，但不必每处装饰都动。动画应与首页流场语言一致，不再成为另一套风格。

### 3. 位置与响应式规则

- 桌面端装饰可沿主要内容容器左右外缘、标题下沿延伸，避免增加外围容器宽度或造成横向溢出。
- 视口 1280–1920px 检查横向花纹是否有完整的起伏形态，不能为了响应式将其压缩成一团细线。
- 768px 下显著减少边角花纹的复杂程度；375px 下只保留短横线和简洁小芽，复杂背景纹理隐藏。
- 表单滚动、展开 `details`、修改 textarea 高度时，花纹应随着布局自然流动，不得使用脱离上下文的固定绝对坐标，造成遮挡或漂浮错位。

## 四、开场与正式页面的视觉连续性

前一轮实现已经建立了 `view-transition-name: idea-seed` 的小球过渡，并通过 `App.tsx` 的 View Transition 组织页面切换。**可以复用这套转场机制，不要重写整个路由。**

但共享对象视觉要改成与新流场一致的**细线凝结点 / 微光圆点**，而不是立体阴影绿珠。进入创作页后它可以自然停在主题标签旁，轻轻延伸成一笔装饰线或小花纹。避免这个点像一个无关的绿色按钮。

- 点击时从真实当前动画状态出发，不要求等首页演出结束。
- 转场先收束主流形，后把共享节点引向主题区；标题与表单错峰衔接，整体流畅而短促。
- 不支持 View Transitions、立即点击、快速往返或 `prefers-reduced-motion` 时仍能直接进入创作页。
- 不复用“纸层折叠、绿珠沿纸面滚动”的动作或动画代码。

## 五、实现技术建议：轻量但有审美表现力

优先考虑 **SVG 负责清晰的主轮廓与线条、Canvas 2D 负责适量细颗粒流场、CSS/WAAPI 负责界面微动效** 的分工；若当前任务复杂度较高，也可以先用全 SVG 实现，但必须保证动态形变**真实连续**，不能只靠 path stroke-dashoffset 画线和几个小球沿固定圆轨道旋转。

建议实现方式：

1. 参数化主流带的**中心流线**和局部宽度，按照时间驱动顶点或路径控制点；基于同一连续状态生成内部流丝，避免每层各自随机运动而互相脱节。
2. 微粒使用稳定的初始种子，并沿连续速度场更新位置，少量随机变化只影响运动细节。不要每一帧重新生成粒子位置或 SVG 路径。
3. 若用 Canvas，限制像素比、粒子数量、滤镜与阴影成本；`requestAnimationFrame` 在页面不可见时暂停，组件卸载时清理资源。
4. 视觉层的参考形态和色彩独立封装，允许快速微调构图而不进入复杂的业务表单代码。
5. 为关键姿态保留可控的时间/进度参数，例如开发预览模式可设置 `pose=0 / .5 / 1`，便于截图对比；正式页面不展示开发控制。
6. `prefers-reduced-motion` 显示高完成度的静态最终姿态，不把整块视觉隐藏。
7. 不要求为此引入 WebGL/Three.js 或大型动画库。**美术效果是验收标准，而技术复杂度不是。** 如现有 SVG/Canvas 不足以达到方案效果，再说明新增依赖的明确收益。

## 六、开发顺序：先把画面做漂亮，再加动态

**P0：美术构图试作**

- 先实现新组件的**高光静态姿态**（占据右侧足够面积、层次丰富、曲线自然、重点集中），给出 1440px 和 1920px 的首屏截图。
- 同时在创作页制作一处横向花纹和一处局部花边，检查不遮挡文本输入。
- 不急着写大段时间循环。静态画面不过关，就先调整形体、颜色、构图、主次与层次。

**P1：实现完整连续流场**

- 根据关键姿态补齐生长、卷曲、分流、合流与稳定状态的连续计算。
- 微粒和气泡跟随主流场；控制密度，避免装饰强于主视觉。
- 用录屏审视整段节奏和自然性，检查是否存在几条线互相穿模、错层、瞬间跳变或突然复位。

**P2：与创作页连贯衔接**

- 用与主流带一致的点／线作为跨页共享元素；保持快速进入及 reduced-motion 的正常使用。
- 微调创作页花纹及高级偏好在不同视口和展开状态下的空间关系。

**P3：回归与审美复核**

- 编译、单元测试、E2E、截图审查并清理失效 CSS 和不再使用的纸艺组件。
- 实际审阅初始（约 0.5s）、高光（约 3s）、静置（约 6s）、按钮跳转，以及 `prefers-reduced-motion` 静态画面。
- **审美上仍然像普通几何练习或随机粒子屏保时，优先调整主体与构图，不以构建通过为完成。**
