# 共享接口契约

> 当前尚未选题或确定服务形态。本文件用于在首次出现跨模块接口时落地契约，**不预先虚构 API**。

## 契约权威来源

- 当前状态：**待确定**。
- 一旦采用 OpenAPI / 代码生成 Schema：在此记录**唯一有效的规范文件或生成地址**，不再手写一份重复字段表。
- 若项目只有少量简单接口、没有自动生成体系：直接在本文件维护契约表即可。

单个接口需要明确：请求字段及类型、必填/可空规则、响应字段及类型、状态码和错误语义。涉及认证、异步任务或幂等性时再补充相应约束。

## 接口变更协议

1. 提出变更：说明原契约、新契约与受影响调用方。
2. 影响另一位开发者的共享语义或破坏性变更，先同步确认；纯内部实现调整可自主完成。
3. 修改**唯一权威契约**、实现和调用方，并完成相关检查；如有 Mock，必须与真实契约一致。
4. 完成后修正失效说明，不留“旧字段 v1 / 新字段 v2”的正文堆叠。重要变化才另记 CHANGELOG。

> 如果是一个全栈应用，也同样适用“共享边界有契约”的思想；不强制为了模板人为拆出两个服务。
