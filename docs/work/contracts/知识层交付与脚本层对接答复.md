# 知识层交付与脚本层对接答复

> 供知识层、脚本层和工作流负责人联调时使用。本文按当前仓库代码与已确认契约说明交付边界，不代表尚未实现的协调器或脚本服务已经可用。

## 知识包交付

知识层生成并保存通过 `KnowledgePackage` Schema 校验的对象后，以实际保存得到的 `artifact_id` 和 `revision` 写入：

```text
${KNOWLEDGE_EXPORT_DIR}/{artifact_id}-r{revision}.json
```

`KNOWLEDGE_EXPORT_DIR` 默认是仓库根目录下的 `.local/knowledge-exports`，可由环境变量覆盖。文件通过同目录临时文件原子发布，之后重新读取并再次执行 Schema 校验。只有读取回来的对象与目标版本一致时，知识层运行才会标记完成并记录该 `ArtifactRef`。已存在的版本只允许相同内容复用；同名但内容不同会报错，不会静默覆盖。

协调器应在该文件可读取后发布：

```json
{"artifact_id": "KP_...", "revision": 1}
```

工作流协调器和脚本服务目前仍未实现。因此，当前知识层负责准备可用的版本文件和精确引用；将该引用写入 `ProjectState.artifacts.knowledge_package` 是后续协调器的职责，不由知识层假造 API 或自行改写共享状态。

## 脚本层读取约定

- 脚本层用项目当前已发布的 `ArtifactRef` 读取同一份版本文件，不自行拼接机器绝对路径，不查询知识层 SQLite，也不调用 Research、Creative 或 Verifier。
- `ProjectState.decisions.direction_id` 若已设置，则使用该方向；否则使用知识包的 `recommended_direction_id`。脚本产物的 `direction_id` 与此选择一致。
- 优先从所选方向的 `knowledge_refs` 取材；其他已核验知识只能作为辅助材料。采用知识时保留其 `conditions`，不要求所有知识都进入成片。
- `constraints.required_knowledge_refs` 表示所有候选方向通用、且当前视频确实不能省略的知识，允许为空。候选内部的 `required_claim_indices` 不映射到这个全局字段。`importance=core` 是优先级提示，不等于强制逐条出镜。
- 已生成脚本继续引用原知识包版本。知识更新产生新 `revision` 后，协调器只有在发布新版本时才更新全局引用；不能让旧脚本自动转向最新版。

## 证据语义

契约负责人已同意在 `evidence.kind` 中增加 `internal_review`，并同步 Schema、示例、校验和知识层生产逻辑。它只描述稳定、低争议、低风险的定义或基础机制所做的具体轻量检查，必须有非空 `details`；不能用虚构 `locator`，也不是外部独立证据。具体数值、时效事实、争议或实验结果，以及重要因果主张，仍需要真实来源或可复核推导。用户预览不显示这类内部检查细节。

## 联调前检查

1. 确认待引用版本文件存在且可解析，`artifact_id`、`revision` 与 `ProjectState.artifacts.knowledge_package` 完全一致。
2. 确认协调器发布了所选方向，并将方向 ID 交给脚本层。
3. 脚本生成后检查 `ProductionScript.knowledge_package_ref` 精确引用该版本，`direction_id` 与项目决策一致。
4. 对选中的非推荐方向再走一遍检查，确认没有把推荐方向的核心 Claim 误设为全局必选知识。

机器字段和引用规则以 `contracts/schemas/`、`contracts/examples/`、`contracts/接口契约与协作规范.md` 及 `contracts/validate_contracts.py` 为准。

## 已确认的 16:9 交付约定

首版 `brief.effective.aspect_ratio` 默认且仅支持 `16:9`，动画以 `1920×1080` 为设计基准，预览按比例缩放。公共 Schema 仍保留通用比例字符串形状。当前知识层在外部模型或搜索调用前拒绝其他比例，并保留原始 `user_input`；不覆盖旧试验、旧产物或历史 ArtifactRef。知识层负责有效配置和早期拦截，动画层负责 1920×1080 设计布局与等比预览。
