# knowledge-show 核心产品与设计原则

> 此处只保留跨模块应长期遵守的稳定决策。完整背景、用户输入体系和内容工作流见 [产品理念与工作流共识](design/产品理念与工作流共识.md)。跨阶段字段以仓库根目录 `contracts/` 为准。

## 一、服务对象与作品目标

创作者可能对知识主题尚不熟悉，也没有编剧、动画或剪辑经验。系统承担知识核验与制作责任，让用户通过**独立、选填的输入项，推荐选项和自由反馈**参与创作。最终观看者面对的是一条线性播放、时长约 2 分 30 秒至 3 分钟的知识视频，而中间产物是连续的播放的动画脚本。

作品优先追求**愿意看下去的吸引力、良好的视觉与音频品质、明确的知识记忆点**。知识事实和关键前提不能错误，但不追求将整个知识体系完整讲完。

## 二、输入与创作自主性

- 主题为唯一必填项；知识细化方向、创作模式、创意想法、必须包含/避免的内容、知识深度、美术偏好、画面比例均可选填。
- **创作模式与美术风格解耦**：模式是“如何讲”（创意优先、直观演示、干货精讲、故事悬念），美术偏好是“看起来怎样”；知识深度是第三个独立维度。
- 系统可以探索并推荐多个候选方向，但**首次生成前不强制用户选择**；用户既可以提前确认，也可以直接采用推荐方向生成可播放预览。
- 用户的明确要求应被保留。系统补全的默认值不得悄悄覆盖明确偏好；用户无需审核专业事实。

## 三、分层交付与创作空间

- **知识层**探索、核验和筛选知识，输出候选方向、充分的可靠素材和重要约束。可以标注视觉潜力，但不提供强制的画面示例或分镜方案。
- **脚本层**决定实际选用哪些知识，以及每个时间段的叙事、事件、文字和音画节奏。脚本指制作时间线，并不预设人物对话形式。
- **动画层**独立决定具体对象、画面语言和连续运动实现，以脚本的时间和语义约束为依据。
- 下游可反馈上游内容缺失或可行性问题，但不得自行改写上游持有的事实和强约束。

## 四、面向反馈的制作方式

- 用户先查看**实际可播放的动态结果**，确认后再导出视频；不能以静态分镜替代动画体验的验收。
- 支持定位到片段或时间范围的自然语言反馈。修改应能够判断涉及知识、脚本还是动画，优先局部重做，保留未受影响内容。
- 各阶段产物与内部对象使用稳定 ID 和版本引用。跨层修改必须保证当前版本关系可追溯，提供必要的撤销或回退能力。
- 自动化检查用于核验知识、数据、时间和运行问题；观感与趣味性需要结合实际预览评价，不能用 Schema 检查代替。

## 五、工程取舍

黑客松阶段优先完成“**输入主题 → 自动探索/可选确认 → 生成脚本 → 可播放预览 → 精准反馈 → 导出**”的完整流程。每次改动尽量小步验证，避免为了未来可能需要的功能引入复杂框架。没有经过实现和验证的设想要明确标为待定。
