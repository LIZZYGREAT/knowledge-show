# knowledge-show 核心产品与设计原则

> 此处只保留跨模块应长期遵守的稳定决策。完整背景、用户输入体系和内容工作流见 [产品理念与工作流共识](design/产品理念与工作流共识.md)。知识层的内部工作原则见 [知识层探索与创意策划](backend/knowledge/知识层探索与创意策划.md)。跨阶段字段以仓库根目录 `contracts/` 为准。

## 一、服务对象与作品目标

创作者可能对知识主题尚不熟悉，也没有编剧、动画或剪辑经验。系统承担知识核验与制作责任，让用户通过**独立的选填输入项、推荐选项和自由反馈**参与创作。最终观看者看到的是一条**线性播放、时长约 2 分 30 秒至 3 分钟**的知识视频；制作过程中则通过实际可播放的动态预览确认效果，再导出成片。

作品追求**愿意看下去的吸引力、良好的视听品质、鲜明的观看体验和明确的知识记忆点**。知识事实与关键前提必须准确，但不以覆盖完整知识体系或堆砌知识数量为目标。

## 二、输入与创作自主性

- 主题为唯一必填项；知识细化方向、创作模式、创意想法、必须包含/避免的内容、知识深度、美术偏好、画面比例均可选填。
- **创作模式与美术风格解耦**：模式描述偏好的讲述方式（创意优先、直观演示、干货精讲、故事悬念），美术偏好描述画面审美；知识深度是独立的第三个维度。
- 系统可以探索并推荐多个候选方向，但**首次生成前不强制用户选择**；用户既可以提前确认，也可以直接采用推荐方向生成可播放预览。
- 用户明确提出的内容和偏好必须保留。系统补全默认值不得覆盖明确要求；用户无需承担专业知识审核。

## 三、知识驱动的创作原则

- **主线先行**：一条视频需要围绕一个足够明确的问题、发现或知识变化推进。内容的引入、解释与结果应存在连续的因果或认知联系，避免无关知识点并排陈列。
- **知识与叙事相互成就**：优先发掘知识规律本身能够推动事件、变化、冲突或发现的可能性。故事、幽默和视觉效果应帮助观众理解知识，避免在故事中机械插入一段讲课。
- **可见的核心对象与变化**：关注知识能否对应明确的对象、关系或状态，让观众有持续可追踪的视觉重心。尽量通过自然、连续、具有原因的变化表达知识，避免只有文字、公式或松散画面切换。
- **创造力不等于固定形式**：不要求每条视频都有角色、剧情反转、固定段数或同一种视觉隐喻。抽象对象、数据、关系、实验现象也可以承担叙事主角。干货精讲同样应有清楚的视觉重心，创意优先同样需要可靠的知识支撑。
- **分层保留创作空间**：知识层考虑核心问题、知识联系与可视化潜力；脚本层负责叙事主线、场景与时间推进；动画层负责具体视觉对象、连续运动和最终画面质量。知识层不向下游强制交付镜头、动画示例或具体实现方案。

## 四、分层交付与修订

- **知识层**探索、核验和筛选知识，输出具有实质差异的候选方向、充分且可靠的共享知识素材和重要约束。知识单元数量由主题和实际需要决定，不设置固定额度。
- **脚本层**决定最终使用哪些知识，以及它们如何形成连续叙事；明确每段的目的、事件、文字和音画节奏，确保知识变化有可理解的前后关系。
- **动画层**独立决定视觉表达，保证对象关系清楚、变化连续、视觉重心明确，并依据脚本语义与时间组织呈现。
- 下游发现内容缺口、解释障碍或实现问题时，可向上游发出有目标的修订请求；不得自行修改其他层持有的知识事实及强约束。

## 五、反馈与工程取舍

- 用户查看**实际可播放的动态结果**并反馈，确认后再导出视频；静态分镜不代替最终观感验收。
- 支持针对片段、事件或时间范围的自然语言反馈，优先局部修订，复用未受影响的成果。
- 阶段产物和内部对象使用稳定 ID、版本和引用；保证新旧版本可追踪，并提供必要的撤销或回退能力。
- 知识真实性、数据一致性和实际动画品质分别检查，不能把 Schema 通过等同于作品完成。
- 黑客松阶段优先完成“**输入主题 → 自主探索/可选确认 → 脚本 → 可播放预览 → 反馈修订 → 导出**”的闭环。只引入能够直接帮助当前目标的流程与抽象，不为创作思路设置机械的数量或结构模板。
