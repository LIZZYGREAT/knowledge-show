# 知识层技术栈路线

> **适用范围**：仅用于 `knowledge-show` 的知识层（`backend/src/knowledge/`），对应的技术选择服务于知识探索、创意策划、事实核验、共享研究素材和人工检验。其余模块的技术栈不在本文确定。
>
> **状态**：知识层首版位于 `feat/knowledge-layer-implementation`，成本效率与体验修订位于 `feat/knowledge-cost-efficiency-ux`；本次联调前修订位于 `feat/knowledge-handoff-readiness`，都尚未合并到 `main`。当前分支在取得共享接口负责人同意后，为 `internal_review` 更新公共契约，并补充原子版本文件交付、结构化输出单次修复和有费用确认的真实预览。知识层尚未接入脚本 Agent、动画层或共享工作流。产品理念以 `docs/work/design-principles.md`、`docs/work/backend/knowledge/知识层探索与创意策划.md` 为依据；对外交付结构以 `contracts/schemas/knowledge-package.schema.json` 为准。

## 一、选型目标

本层要把一个用户主题转化为**有吸引力的候选方向、能够支撑创作的知识素材和必要的事实依据**。最终观看者是普通观众，目标成片通常为 2 分 30 秒至 3 分钟。系统需要帮助创作者主动发现值得讲述的内容，不能最终只产出百科摘要或一套 PPT 式知识卡片。

技术选型主要服务四件事：让 Research、Creative、Verifier 可靠调用模型；让外部搜索和模型已有知识共同参与研究；让多个角色复用同一批知识与证据；让开发者能**输入自定义研究主题，在浏览器里直接观察真实输出、运行过程和问题**。

总体取舍：**单一 Python 服务内的轻量编排 + DeepSeek Flash + DeepSeek Search/Fetch + SQLite + 独立 Streamlit 人工检验页**。第一阶段不引入多 Agent 框架、向量数据库、消息队列或独立检索服务。是否扩展取决于实际功能缺口。

## 二、确定与建议采用的技术

| 位置 | 技术 | 职责与选择理由 | 采用方式 |
| --- | --- | --- | --- |
| 模型 | **DeepSeek `deepseek-flash`** | Research、Creative、Verifier 共用一个模型能力，通过不同任务说明和所需资料区分职责 | 已确定 |
| 外部检索 | **DeepSeek Search API** | 围绕具体研究问题检索网页，得到可筛选的标题、URL、摘要及相关信息 | 已确定 |
| 网页阅读 | **DeepSeek Fetch API** | 只对值得核验或补充细节的来源抓取 Markdown 正文 | 已确定 |
| 语言与运行 | Python 3.11+ | 后端知识层与测试入口使用同一语言，便于 SQLite、模型调用与数据校验 | 已采用，仓库 `.venv` 使用 Python 3.11 |
| 模型客户端 | `openai` Python SDK | 使用 DeepSeek 兼容的 Responses API；集中封装调用和错误处理 | 已采用 |
| 搜索客户端 | `httpx` | 直接访问 Search/Fetch JSON 接口，统一超时、错误和请求记录 | 已采用 |
| 内部结构 | Pydantic 2 | 约束 ResearchTask、Source、Claim、CreativeLead、Issue 等内部对象，减少无效数据流转 | 已采用 |
| 共享存储 | Python 内置 `sqlite3` | 轻量保存同项目的研究问题、资料、知识主张、证据与执行记录 | 已采用，按项目隔离并复用来源 |
| 内部检索 | SQLite 查询、关键词/别名与关系扩展 | 先根据主题、相关 Claim、知识依赖和状态返回小范围上下文；不强制向量检索 | 已采用 |
| 正式契约校验 | `jsonschema` | 验证实际 `KnowledgePackage` 是否符合共享 Schema | 已采用；当前分支经同意增加 `internal_review` 并同步校验 |
| 人工检验页 | **Streamlit** | 配有密钥时用户预览走在线生成并要求费用确认；未配置时只提供固定主题离线示例；开发者诊断可切换 Mock/Real API | 当前分支已实现，未连接正式前端 |
| 自动化测试 | `pytest` + 假客户端/固定 Mock | 不消耗 API 额度测试调度、存储、引用与失败路径 | 已采用 |
| 环境配置 | 环境变量 + `python-dotenv`（本机开发） | 保存 API Key、模型、超时及数据路径；真实密钥不进入 Git | 已采用，自动加载仓库根目录 `.env` |

这里的“Agent”是逻辑角色，**不等于三个常驻进程**。同一个 Flash 客户端可根据 Research、Creative、Verifier 的不同任务接收不同上下文。协调器使用普通 Python 调度代码即可。

### 本地虚拟环境与依赖安装

直接依赖清单已放在 [`backend/requirements-knowledge.txt`](../../../backend/requirements-knowledge.txt)。根目录 [`requirements.txt`](../../../requirements.txt) 是当前 Python 3.11 虚拟环境的完整 `pip freeze` 快照，包含传递依赖，可用于复现本次解析出的版本。知识层使用 Python 3.11 或更新版本。

Ubuntu / WSL 使用 Bash，在仓库根目录执行。命令用 uv 管理独立的 Python 运行时，不替换系统 Python；如已安装 uv，可跳过安装脚本：

```bash
if ! command -v uv >/dev/null 2>&1; then
  curl -LsSf https://astral.sh/uv/install.sh | env UV_INSTALL_DIR="$PWD/.local/uv/bin" sh
fi
export PATH="$PWD/.local/uv/bin:$PATH"
export UV_PYTHON_INSTALL_DIR="$PWD/.local/uv/python"
export UV_PYTHON_BIN_DIR="$PWD/.local/uv/bin"
uv python install 3.11
uv venv --seed --python 3.11 .venv
source .venv/bin/activate
python -m pip install --upgrade pip
python -m pip install -r backend/requirements-knowledge.txt
# 若要复现 requirements.txt 中完全相同的解析版本，可改用：
# python -m pip install -r requirements.txt
python -m pip check
```

Windows PowerShell 可先用 WinGet 安装 uv，然后创建相同版本的环境：

```powershell
winget install --id=astral-sh.uv -e
uv python install 3.11
uv venv --seed --python 3.11 .venv
.\.venv\Scripts\Activate.ps1
python -m pip install --upgrade pip
python -m pip install -r backend/requirements-knowledge.txt
# 若要复现 requirements.txt 中完全相同的解析版本，可改用：
# python -m pip install -r requirements.txt
python -m pip check
```

`python-dotenv` 在启动时自动读取仓库根目录 `.env`；若本地还没有该文件，再从配置模板 [`.env.example`](../../../.env.example) 复制并填写 API Key。不要覆盖已有的 `.env`。Streamlit 的监听地址和端口可在启动进程前设置。Ubuntu / WSL 在 Bash 中执行：

```bash
test -f .env || cp .env.example .env
# 若新建了 .env，在编辑器中填写 DEEPSEEK_API_KEY。
export PYTHONPATH="$PWD/backend/src"
```

`KNOWLEDGE_DATA_DIR` 指向 `.local/knowledge-data`，`KNOWLEDGE_EXPORT_DIR` 指向 `.local/knowledge-exports`；目录均已由 `.gitignore` 排除。检验页只监听 `127.0.0.1:8501`。Windows PowerShell 可复制模板、在编辑器中填写密钥，并在启动应用前导出配置：

```powershell
Copy-Item .env.example .env
# 编辑 .env 填写 DEEPSEEK_API_KEY；应用启动时由 python-dotenv 读取。
$env:DEEPSEEK_BASE_URL = "https://api.deepseek.com"
$env:DEEPSEEK_MODEL = "deepseek-flash"
$env:DEEPSEEK_TIMEOUT_SECONDS = "60"
$env:KNOWLEDGE_DATA_DIR = ".local/knowledge-data"
$env:KNOWLEDGE_EXPORT_DIR = ".local/knowledge-exports"
$env:STREAMLIT_SERVER_ADDRESS = "127.0.0.1"
$env:STREAMLIT_SERVER_PORT = "8501"
$env:STREAMLIT_SERVER_HEADLESS = "true"
$env:PYTHONPATH = Join-Path $PWD "backend/src"
```

知识层将公共 `KnowledgePackage` 按 `{artifact_id}-r{revision}.json` 导出到 `KNOWLEDGE_EXPORT_DIR`，通过原子发布、读取回验和 Schema 校验后才标记运行完成。已发布版本不可被不同内容覆盖。另有不含密钥/模型私有推理的独立运行摘要。

环境命令依据：[uv 安装文档](https://docs.astral.sh/uv/getting-started/installation/)、[uv Python 管理文档](https://docs.astral.sh/uv/guides/install-python/)、[Python venv 文档](https://docs.python.org/3/library/venv.html)、[Streamlit 命令行安装文档](https://docs.streamlit.io/get-started/installation/command-line)、[Streamlit 配置选项](https://docs.streamlit.io/develop/concepts/configuration/options)。

## 三、DeepSeek API 接入边界

本路线使用以下接口，并已在当前实现分支以实际账户完成连通性和端到端验收。

| 目的 | 模型或端点 | 关键说明 |
| --- | --- | --- |
| 文本/结构化模型输出 | 模型名 `deepseek-flash`，Responses API；`base_url=https://api.deepseek.com` | 普通探索可输出自然语言；需要稳定传递的中间结果可用 `text.format=json_schema`，落库前仍执行本地验证 |
| 网页搜索 | `POST https://api.deepseek.com/v1/tools/search` | 发送 `query`，可选 `count`；主要获取结果概览，按需继续阅读原文 |
| 网页抓取 | `POST https://api.deepseek.com/v1/tools/fetch` | 发送 `url`，读取返回的 `title` / `content` |

以上使用同一个 `DEEPSEEK_API_KEY`，由程序在请求头中传递 Bearer Token。DeepSeek Responses API 的内置 `web_search` 当前支持 `deepseek-v4-pro`；本路线采用 `deepseek-flash`，因此由 Python 协调器显式调用独立 Search/Fetch，避免把模型提示词中的“请联网搜索”误当成真实执行。

官方依据：

- [DeepSeek Responses API 使用说明](https://api-docs.deepseek.com/guides/responses_api/)
- [DeepSeek Responses API 请求与结构化输出](https://api-docs.deepseek.com/api/create-response/)
- [DeepSeek Search & Fetch 指南](https://api-docs.deepseek.com/guides/search/)
- [DeepSeek Search 请求](https://api-docs.deepseek.com/api/search/)
- [DeepSeek Fetch 请求](https://api-docs.deepseek.com/api/fetch/)

完整配置模板见根目录 [`.env.example`](../../../.env.example)：

```dotenv
DEEPSEEK_API_KEY=
DEEPSEEK_BASE_URL=https://api.deepseek.com
DEEPSEEK_MODEL=deepseek-flash
DEEPSEEK_TIMEOUT_SECONDS=60
KNOWLEDGE_DATA_DIR=.local/knowledge-data
KNOWLEDGE_EXPORT_DIR=.local/knowledge-exports
STREAMLIT_SERVER_ADDRESS=127.0.0.1
STREAMLIT_SERVER_PORT=8501
STREAMLIT_SERVER_HEADLESS=true
```

真实密钥只存放在被 `.gitignore` 排除的 `.env` 或进程环境变量中，不上传日志、Mock 和人工检验导出文件。`DEEPSEEK_MODEL` 只允许由应用配置读取，不将模型名写入 `KnowledgePackage` 的公共字段。

## 四、知识获取与统一管理

知识来源分为三条途径：模型已有知识、可复核的计算/推导、外部 Search/Fetch 资料。**产生一条 Claim 不等于核验通过**。模型可以直接写出基础概念和常见原理，再由 Verifier 适度核查；具体数据、历史事实、反直觉结论和重要争议需要更可信的外部依据或可复核方法。

共享状态以逻辑对象组织：`ResearchQuestion/ResearchTask`、`Source`、`Claim`、`ClaimEvidence`、`CreativeLead`、`Issue` 和运行记录。第一阶段使用 SQLite 作为统一存储，提供少量固定查询方法；各角色不得各自维护不受管理的知识副本。完整原文可以放在可配置的本地文件目录，以数据库保存引用和摘要，避免数据库与上下文都被长文本塞满。

内部检索的第一阶段只需要：关键词、同义术语、来源/状态过滤、Claim 关联和前置依赖展开；如内容过多，可让 Flash 对召回的小批候选做相关性筛选。**先实现按任务准确找到所需知识**，实际遇到中英文同义词或大规模召回失败时，再考虑 SQLite FTS5、embedding 或其他检索方案。

Pydantic 负责知识层**内部对象**，`jsonschema` 负责现有**跨阶段公共对象**。不要把内部数据库字段直接暴露为新公共接口，也不要维护第二份 `KnowledgePackage` 字段定义。

## 五、本地人工检验入口

人工检验入口已用 `Streamlit` 构建为**独立的本地浏览器页面**，位于知识层自己的 `devtools/` 下，不占用 `frontend/` 工作区。它调用知识层正式入口 `generate_knowledge_package`，Mock 和 Real API 共用同一工作流和运行状态。配有密钥时用户预览会在点击前显示在线调用费用提示，并要求勾选确认；没有密钥时页面标明离线固定示例及支持主题，其他主题会在启动运行前被拒绝。页面打开不会自动调用模型。

页面按两类使用者转换展示信息：

1. 输入任意知识主题，按需填写具体方向、创作模式、知识深度、用户创意、必须包含/避免内容；采用项目 Brief 的真实语义。
2. 用户预览以简明进度和友好错误提示呈现运行状态，不显示 Agent、搜索次数、Run ID、证据 ID、API 原始错误或模型输出。
3. 结果优先显示推荐方向、其他候选、核心问题、知识看点、学习收获和必要条件；反馈入口使用自然语言，并说明本地反馈不会自动改写当前结果。
4. 开发者诊断视图保留 Claim、证据、运行事件、状态、内部错误和下载功能，供本机排查使用。
5. 运行失败时不显示未验证知识为成功结果；`internal_review` 只用于有具体说明的稳定低风险基础知识，不展示给普通用户，也不能替代高风险主张所需的来源或推导。

当前分支的真实 API 验收覆盖了基础定义、进阶自注意力机制，以及带有 `focus` 和 `must_include` 的骰子概率主题；结果均通过知识包校验。自动测试还覆盖多候选方向切换、证据范围和版本交接。验收计数记录在 `STATUS.md` 与 `docs/work/logs/CHANGELOG.md`。

此页的目的只是让开发者能回答“我输入这个研究问题，知识层到底给出了什么、为什么是这些内容、靠不靠谱、值不值得做成视频”。

激活仓库 `.venv` 后，在仓库根目录启动检验页。有密钥时用户预览默认走 Real API，并需确认可能产生调用费用；无密钥时只提供固定离线示例。开发者诊断可手动选择 Mock / Real API：

```bash
PYTHONPATH=backend/src STREAMLIT_SERVER_ADDRESS=127.0.0.1 STREAMLIT_SERVER_PORT=8501 .venv/bin/python -m streamlit run backend/src/knowledge/devtools/review_app.py
```

页面默认仅监听本机；运行历史、人工评价和本地导出数据写入 `.local/`，该目录已从 Git 排除。
